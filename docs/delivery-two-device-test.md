# 外送雙裝置手動測試

一台手機當顧客（NavPilot 首頁），另一台當外送員（同一個 Preview 網址的 `/courier`）。兩台都要能開定位，或外送員改按「用臺南示範位置上線」。

先決條件：

1. Migration `supabase/migrations/20261030133000_delivery_portal.sql` 已由擁有者套用到 **NavPilot** `rxzbsthsqlozxgctdoks`。不要套到其他專案。
2. 伺服器已有既有的 `NEXT_PUBLIC_SUPABASE_URL`（主機必須是 `rxzbsthsqlozxgctdoks.supabase.co`）與 `SUPABASE_SERVICE_ROLE_KEY`。不要新增密鑰，不要把 service role 放進 `NEXT_PUBLIC_`。
3. Preview 不要設定 `DELIVERY_PROVIDER=memory`。沒設定時走 Supabase。
4. 功能旗標在 Preview 預設開啟。若菜單沒有「外送」，確認 `DELIVERY_PORTAL_ENABLED` 不是 `0`。

表還沒建時，兩邊都會看到「外送資料表尚未建立」，不會寫入半筆訂單。

也可以先對本機單一行程跑自動檢查（記憶體 provider，不能代表正式環境）：

```bash
DELIVERY_PROVIDER=memory npm run dev
# 另一個終端
npm run test:delivery:http
```

`scripts/delivery-two-device-check.mjs` 會走同一套 HTTP：最近外送員逾時不在這支腳本裡（單元測試覆蓋），腳本覆蓋下單、接單、取餐、送達，以及兩位外送員同時搶單只有一人成功。

## 顧客

1. 打開首頁，點右下功能選單（格子圖示）。
2. 點「外送」。
3. 選一間店，把餐點數量加到至少 1。
4. 派單模式先選「最近外送員」。
5. 點「送出訂單」。金額應為 0，沒有付款畫面。
6. 狀態應停在「等待外送員接單」，地圖上有店與送達點。

## 外送員（最近外送員）

1. 另一台打開 `/courier`。
2. 點「上線並分享位置」。定位失敗就點「用臺南示範位置上線」。示範座標在臺南中西區，離種子店家約數公里內。
3. 幾秒內應出現剛才那筆訂單，附逾時時間。
4. 點「接受」。顧客那台應改成「外送員已接單」，地圖出現「送」標記，並跟著輪詢移動。
5. 外送員地圖應看到「收」（送達點）與「客」。
6. 點「已取餐」，顧客狀態變成「已取餐」。
7. 點「已送達」，顧客狀態變成「已送達」。

婉拒或乾等逾時（預設 45 秒）：訂單應改派給下一位範圍內、上線且閒置的外送員。只有一位時，逾時後回到沒有指派的等待。

## 搶單

1. 顧客再下一筆，模式改「搶單」。
2. 兩位外送員都上線，而且都在取餐點 3 公里內。
3. 兩邊都看得到同一筆。
4. 幾乎同時按「接受」。只有一邊變成進行中，另一邊看到訂單消失或「已經被其他外送員接下」。
5. 範圍外的第三位不應看到這筆。

## 隔離

- 第三台沒有這筆訂單代號的顧客，不應在畫面上看到別人的狀態或外送員位置。
- 未上線、或超出半徑的外送員，不應看到搶單。
